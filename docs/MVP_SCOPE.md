# Границы MVP

## Два уровня готовности

**Первый вертикальный срез** — небольшое сквозное приложение с настоящим исполнением. **Полный MVP** — исходный набор базовых интеграций и командной работы. Срез не подменяет полный MVP, а даёт раннюю точку проверки архитектуры.

| Возможность | Первый срез | Полный MVP |
|---|---|---|
| Вход/выход/регистрация | Да, личная организация создаётся автоматически | То же + создание организаций |
| Проекты | Создать, изменить, архивировать | То же |
| Участники | Только owner, модель membership уже есть | Приглашение по одноразовой ссылке, owner/editor/viewer |
| Источник | CSV upload | CSV, JSON file, PostgreSQL, MySQL, REST GET |
| Получатель | Скачиваемый CSV | CSV, PostgreSQL, MySQL, REST POST/PUT |
| Преобразования | Filter, Map/Rename | То же + явное приведение типов |
| Данные и schema | Dataset v1: schema + batch records; manual/simple CSV schema | Basic schema propagation, field mapping, simple inference |
| Граф | Линейный через общий формат nodes/edges | Один источник, несколько получателей, fan-out |
| Запуск | Вручную, асинхронно | То же |
| Наблюдение | Статусы запуска и узлов, ошибка, результат | История, фильтры, структурированные логи |
| Обновление UI | Polling | Polling |

CSV/JSON — файловые assets, а не подключения с credentials. REST поддерживает фиксированный JSON-формат и bounded response; универсальный OAuth и произвольные схемы пагинации отложены. Полный список capabilities находится в [NODE_CONTRACT](NODE_CONTRACT.md).

## Ограничения исполнения v0.1

- DAG: циклы запрещены. Один source; transform/destination имеют один вход. Fan-in и несколько источников отложены до Join.
- Fan-out передаёт одинаковый результат нескольким узлам; это не условное ветвление. Ветви исполняются последовательно, в детерминированном порядке.
- На pipeline разрешён один активный запуск (`queued` или `running`); повторная независимая команда получает 409.
- Предлагаемые начальные лимиты: 50 узлов, 100 связей, 10 000 записей в наборе, 10 MiB входного файла/HTTP-ответа, 50 MiB промежуточных сериализованных данных на запуск, 5 минут на запуск, 30 секунд на одну внешнюю операцию. Значения конфигурируемые; это защитные пределы, не показатели производительности.
- При первой ошибке прекращаем запуск, ещё не начатые узлы получают `skipped`. Уже записанные внешние данные не откатываются глобально.
- Общего автоматического retry нет. Повтор пользователем создаёт новый Execution и может повторить побочные эффекты.
- Dataset v1 batch-oriented. Chunking, pagination, streaming, backpressure и distributed execution — точки расширения, не обязательные функции MVP.
- Schema помогает UI и validation, но не является абсолютной гарантией качества данных. Runtime всё равно проверяет отсутствующие поля, типы и лимиты во время исполнения.

## После MVP

Расписания; Sort/Group; Join/Aggregate; Data Quality; Deduplicate; условия; schema inference/evolution; lineage; большие объёмы и streaming; автоматические безопасные retries; WebSockets; входящие webhooks; Google Ads/Analytics/Sheets; SDK, AI, MCP, subpipelines; распределённое исполнение.

S3 не входит в начальный план. Возвращаться к нему только при новой потребности, не добавлять MinIO как скрытую обязательную зависимость.

## Приёмка полного MVP

- Связать все заявленные типы источников/получателей хотя бы интеграционными сценариями в тестовой среде.
- Собрать поток через UI, сохранить, перезагрузить страницу и исполнить тот же граф.
- Изменить граф во время исполнения: текущий запуск использует старый снимок.
- Повторить доставку job: внешние действия не стартуют второй раз для того же активного Execution.
- Убить worker: запуск перестаёт бесконечно отображаться работающим, показано состояние с неопределённым внешним результатом.
- Проверить изоляцию организаций, скрытие секретов, ресурсные лимиты и скачивание результата с авторизацией.
- Запустить проект из чистого checkout по README; реальные команды CI проходят.
