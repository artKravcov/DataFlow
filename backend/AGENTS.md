# Backend — Laravel API

Перед изменениями прочитай `../AGENTS.md`, `../PROJECT_CONTEXT.md`, `../docs/MVP_SCOPE.md` и документы, относящиеся к текущей задаче. Корневой `AGENTS.md` имеет приоритет.

## Область ответственности

- В этой папке находится Laravel API: авторизация, границы организаций, проекты, pipeline-графы и состояния запусков.
- Используй уже закреплённые зависимости и Laravel API текущей версии. Не устанавливай и не обновляй зависимости без отдельной необходимости в задаче.
- Для типового Laravel-кода можно использовать `php artisan make:* --no-interaction`, затем адаптировать результат к проекту.
- Не добавляй в MVP AI/MCP, Kafka, Kubernetes, marketplace, billing или микросервисы.

## Инварианты

- Проверяй membership и роль для каждой операции и вложенного ресурса; ресурсы разных организаций недоступны друг другу.
- Laravel — единственный компонент, который пишет в базу приложения. Worker взаимодействует через внутренний API.
- Не помещай секреты в граф, Redis, ответы браузеру, логи или фикстуры.
- Сохраняй граф атомарно с проверкой revision; сервер обязан проверить DAG, порты и принадлежность связанных ресурсов организации.

## Проверки

- Используй команды из актуального `README.md` и Composer scripts.
- После PHP-изменений запускай форматирование и релевантные тесты, когда окружение доступно.
- В финальном сообщении укажи, что проверено фактически, что не запускалось и какой следующий разумный шаг.
