# Качество и минимальная безопасность

Меры ниже — проектные требования для конкретных функций MVP. Это не заявление о готовности к публичному SaaS.

## Проверки по границам

| Область | Обязательные сценарии |
|---|---|
| Auth/tenancy | Две организации; чужие nested ID для graph, execution, asset, connection; запрещённые роли |
| Membership | Принятие чужого email/token, expiry, повтор ссылки, конкурентное удаление последнего owner |
| Граф | Цикл, disconnected node, неизвестный тип, port mismatch, второй вход, revision conflict |
| Worker | Реальная очередь, duplicate delivery, потеря claim response, lease expiry, late events |
| Коннекторы | Timeout, неверный schema, пустой набор, row/byte limit, частичная внешняя запись |
| Файлы | Oversize, повреждённый CSV/JSON, путь обхода каталогов, скачивание чужого результата |
| Сквозной UI | CSV пример из EXECUTION_FLOW и понятная ошибка неправильного mapping |

Для node handlers — небольшие unit tests преобразований; для tenant policies/DB constraints — интеграционные тесты на PostgreSQL; для протокола — общий набор fixtures PHP/TS и настоящий Redis. End-to-end тестировать один основной путь и критические ошибки, не каждый вариант верстки.

## Секреты

Connection credentials шифруются backend; ключ находится вне БД и Git. В API metadata возвращается только наличие секрета. Worker получает секреты нужных connections через внутренний защищённый канал, держит их в памяти и не пишет в logs. Log context строится по allowlist, без raw HTTP bodies, headers, DSN и строк пользовательских данных по умолчанию.

Auth, invitations и запуск ограничиваются rate limits. Cookie/session и CSRF настройки проверяются на реальном dev origin. Internal API требует service identity плюс lease для операций запуска; наличие execution ID не авторизация.

## Сеть и коннекторы

Произвольные URL/DB hosts дают worker доступ к сети. На старте разрешать только настроенный оператором список targets. Запретить loopback, link-local, metadata endpoints и внутренние сервисы приложения; локальные тестовые DB/REST адреса разрешаются явным dev allowlist. Проверять разрешённый resolved IP при подключении, каждый redirect и порт; запрет redirects по умолчанию упрощает REST MVP. Сетевые ограничения контейнера усиливают проверку URL.

Не разрешать `file:`, произвольные URL credentials или путь вне base URL. DNS rebinding и обход через альтернативные IP-форматы входят в проверки before public exposure. DB credentials имеют минимальные права на тестовую/целевую таблицу; SQL identifiers проверяются, values параметризуются.

## Файлы и ресурсы

Storage key генерирует сервер; original_name только display metadata. Uploaded файл не исполняется и не попадает в web root. Лимитировать поток чтения/загрузки по bytes, количество rows/columns и размер полей, а также суммарный intermediate budget из MVP_SCOPE. Не доверять одному Content-Length.

CSV export экранирует разделители/кавычки/переносы строк. Предложение по умолчанию: spreadsheet-safe export нейтрализует строковые ячейки, начинающиеся с `=`, `+`, `-`, `@`, tab или CR; документировать, что это меняет представление таких строк. Числовые значения записывать как числа. Точное сохранение строк для машинного обмена — отдельный явно выбранный режим с объяснением в UI.

Общий timeout, timeout операций и process memory limit обязательны уже в срезе. Логи ограничены по размеру сообщения и числу событий: предложение 4 KiB/message и 1000 log entries/run, затем одно сообщение об усечении. События состояния сохраняются отдельно от лимита диагностических сообщений.

## Перед публичным доступом

Отдельный этап: backup/restore БД и encrypted credentials, retention assets/logs, TLS, сетевые ограничения, лимиты пользователей, актуальные зависимости и мониторинг. Эта работа не блокирует локальный учебный сценарий, но её нельзя считать сделанной только по наличию Docker.
