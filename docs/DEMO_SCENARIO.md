# Сценарий показа прототипа

Длительность: 2–3 минуты. Демонстрация показывает реальное выполнение локального CSV-потока, а не заранее записанный результат.

## Подготовка

1. В `.env` задайте `DATAFLOW_DEMO_ADMIN_EMAIL`, пароль от 12 символов, действительный `INTERNAL_SERVICE_TOKEN` длиной не менее 32 символов и `DATAFLOW_WORKER_ENABLED=1`.
2. Выполните команды из [README](../README.md): поднимите Docker Compose, примените миграции, затем `db:seed` и профиль `runtime`.
3. Откройте `http://localhost:8080` и войдите как `demo-owner@dataflow.local` с паролем из `.env`.

## Показ

1. Выберите **DataFlow Demo Organization** → **Демонстрация DataFlow** → **Платные заказы**.
2. Покажите четыре блока и настройки: CSV источник, Filter `status equals paid`, Map `order_id → id` и `total → amount`, CSV результат.
3. Обновите страницу: граф остаётся сохранённым.
4. Нажмите **Запустить**. Панель «Запуски» сначала покажет очередь, затем состояния блоков и статус «Завершён».
5. Скачайте `paid-orders.csv` и покажите содержимое:

```csv
id,amount
101,12.50
103,20.00
```

## Что можно пояснить преподавателю

- Запуск получает неизменяемый снимок графа: последующее редактирование не меняет уже поставленную задачу.
- Laravel сохраняет состояние и проверяет доступ организации; Node worker не пишет в базу напрямую.
- Redis используется только для доставки задания. При повторной доставке активный запуск не исполняется второй раз.
- CSV хранится в приватном volume и доступен по авторизованной ссылке только участникам организации.

## Ограничения текущей версии

Это первый вертикальный срез: один линейный CSV-поток и ручной запуск. PostgreSQL/MySQL/REST-коннекторы, JSON, fan-out, приглашения и расписания в демонстрацию не входят.
