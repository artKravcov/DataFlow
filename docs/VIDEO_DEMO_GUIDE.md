# Гайд для видео и первого показа DataFlow

Этот сценарий рассчитан на 3–5 минут. Он показывает реальную работу приложения: входной CSV проходит через визуально настроенный поток, worker создаёт новый CSV, а пользователь скачивает его из интерфейса.

Для короткого показа используйте готовый поток из seed. Не создавайте граф во время записи: это дольше и повышает шанс опечатки. Сборку графа можно показать отдельным фрагментом после основного результата.

## Что нужно подготовить один раз

Работать нужно из корня проекта `C:\DataFlowPetProject\DataFlow`.

1. В локальном файле `.env` должны быть заданы:

   ```dotenv
   DATAFLOW_DEMO_ADMIN_EMAIL=ваш-локальный-email
   DATAFLOW_DEMO_PASSWORD=пароль-длиной-не-меньше-12-символов
   INTERNAL_SERVICE_TOKEN=случайная-строка-длиной-не-меньше-32-символов
   DATAFLOW_WORKER_ENABLED=1
   ```

   Не показывайте `.env` в видео: там находятся локальные пароли и служебный токен.

2. Поднимите приложение, примените структуру базы, создайте demo-данные и включите обработку запусков:

   ```powershell
   docker compose up --build --wait
   docker compose exec backend php artisan migrate --force
   docker compose exec backend php artisan db:seed
   docker compose --profile runtime up --build -d worker queue-manager
   ```

3. Откройте `http://localhost:8080`. Если страница не открывается, выполните `docker compose ps` и дождитесь, когда `gateway`, `backend`, `frontend`, `postgres` и `redis` станут healthy/running.

4. Войдите под учётной записью:

   - email: `demo-owner@dataflow.local`;
   - пароль: значение `DATAFLOW_DEMO_PASSWORD` из `.env`.

Seed можно запускать повторно. Он не перезаписывает уже настроенный demo-поток, поэтому после собственной правки графа для полностью чистого примера проще вернуть настройки вручную из раздела «Контрольные данные» ниже.

## Сценарий записи

### 0:00–0:20 — что это за продукт

На экране выбора организаций выберите **DataFlow Demo Organization**. Скажите:

> DataFlow позволяет собрать поток обработки данных без написания кода. В этом примере я беру CSV с заказами, оставляю только оплаченные и формирую новый CSV для скачивания.

Откройте **Демонстрация DataFlow** → **Платные заказы**.

### 0:20–1:10 — показать визуальный поток

На странице потока видны четыре блока. Щёлкните по ним по порядку и коротко поясните:

1. **CSV источник** — уже выбран входной файл `paid-orders.csv`.
2. **Фильтр** — поле `status`, условие «Равно», значение `paid`. Он исключает неподтверждённые заказы.
3. **Сопоставление** — оставляет нужные поля и переименовывает `order_id` в `id`, `total` в `amount`.
4. **CSV результат** — создаёт отдельный файл `paid-orders.csv`.

Покажите связи между блоками. Затем обновите страницу браузера и скажите:

> Граф сохраняется на сервере. После обновления страницы настройки и связи остаются на месте.

### 1:10–2:10 — запустить и дождаться результата

Нажмите **Запустить** в верхней части страницы.

В панели **Запуски** сначала появится статус «В очереди», затем «Выполняется» и «Завершён». Дождитесь «Завершён» и скажите:

> Для запуска сохраняется снимок текущего графа. Поэтому даже если позже изменить схему, уже начавшийся запуск использует прежнюю версию. Обработка идёт отдельным worker-процессом, а интерфейс показывает сохранённый статус.

Если статус не меняется более 15 секунд, до записи проверьте, что worker и queue-manager запущены:

```powershell
docker compose --profile runtime ps
docker compose logs --tail=50 worker queue-manager
```

### 2:10–2:40 — показать файл-результат

В завершённом запуске нажмите ссылку скачивания результата. Откройте CSV в текстовом редакторе или таблице. Должно быть:

```csv
id,amount
101,12.50
103,20.00
```

Скажите:

> Из трёх строк входного файла две имеют статус paid. Они попали в новый файл, а нужные поля получили понятные имена.

### 2:40–3:10 — показать историю

Откройте в меню **Обзор**. Здесь отображается история запусков всех потоков выбранной организации. Покажите фильтр **Завершён** и переход по записи обратно в поток.

Скажите:

> История изолирована по организациям: пользователь видит только свои запуски. Активные запуски страница обновляет автоматически.

### 3:10–3:30 — финал

> В прототипе уже есть авторизация, организации и роли, визуальный редактор, проверка графа, реальный CSV runtime и скачивание результата. Следующими шагами будут новые источники данных и коннекторы, например JSON и REST.

## Контрольные данные

Если нужно пересобрать demo-поток вручную, используйте входной CSV:

```csv
order_id,status,total
101,paid,12.50
102,pending,8.00
103,paid,20.00
```

Соедините блоки строго в таком порядке:

```text
CSV источник → Фильтр → Сопоставление → CSV результат
```

Настройки фильтра: `status` → «Равно» → `paid`.

Сопоставления:

| Исходное поле | Новое имя |
|---|---|
| `order_id` | `id` |
| `total` | `amount` |

У результата задайте имя `paid-orders.csv`, затем сохраните граф перед запуском.

## Что не стоит обещать в видео

Это первый рабочий вертикальный срез. Не заявляйте, что уже реализованы REST, JSON, PostgreSQL/MySQL-коннекторы, расписания, приглашения участников, fan-out или автоматические повторы внешних записей: эти функции ещё не входят в текущую версию.

## Быстрый чек-лист перед записью

- [ ] `http://localhost:8080/api/ready` отвечает `200`.
- [ ] В `.env` включён `DATAFLOW_WORKER_ENABLED=1`.
- [ ] Запущены `worker` и `queue-manager` через профиль `runtime`.
- [ ] Выполнен `db:seed` и доступен пользователь `demo-owner@dataflow.local`.
- [ ] Один тестовый запуск уже прошёл успешно, а окно браузера затем обновлено перед началом записи.
- [ ] Открыта организация **DataFlow Demo Organization**, проект **Демонстрация DataFlow** и поток **Платные заказы**.
