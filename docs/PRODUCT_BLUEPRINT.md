# Продуктовый blueprint

## Задача

Данные разбросаны по файлам, API и базам. Для общего результата человек вручную выгружает части, меняет поля и переносит их в другое место. DataFlow сохраняет этот процесс как визуальный поток, который можно запускать повторно и наблюдать за его выполнением.

Ценность — воспроизводимая цепочка работы с понятными настройками и объяснимыми ошибками. Это продуктовая гипотеза; сравнение с конкурентами и рыночный спрос пока не исследованы.

## Пользователи и сценарии

| Пользователь | Задача | Пример результата |
|---|---|---|
| Аналитик | Привести выгрузки к общей структуре | CSV заказов с одинаковыми именами полей |
| Разработчик | Передать данные между системами | Строки MySQL записаны в PostgreSQL |
| Маркетолог | Подготовить данные для анализа | Отфильтрованные кампании в таблице; рекламные коннекторы позже |

Одна платформа и одна модель графа для всех ролей. В перспективе — пользовательские интеграции и автоматизация разработки. Выполнение deployment-команд, управление инфраструктурой и изменение рекламы автоматически не входят в начальную версию.

## Основной путь

1. Войти, выбрать организацию, создать проект.
2. Добавить подключение или загрузить файл.
3. Создать pipeline, выбрать источник и блоки преобразований.
4. Соединить блоки; увидеть причину недопустимой связи.
5. Настроить получателя, сохранить и проверить граф.
6. Запустить вручную; увидеть очередь, текущий узел и результат.
7. При ошибке открыть проблемный узел, исправить конфигурацию и создать новый запуск.

## Интерфейс

Главная показывает текущие работы, недавние ошибки и последние завершения. После появления расписаний — следующие запуски. Количество запусков и длительность доступны в деталях, но не являются центром dashboard. Не показывать фиктивные проценты прогресса, когда объём неизвестен.

Редактор: каталог блоков слева, граф в центре, настройки выбранного блока справа. Для каждого поля — понятная подпись, пример и ошибка рядом. Названия вроде «Источник CSV» и «Переименовать поля» предпочтительнее внутренних type identifiers.

## Успех первой версии

Пользователь без редактирования кода собирает CSV → Filter → Map → CSV, получает ожидаемый файл и понимает причину намеренно вызванной ошибки. Второй пользователь другой организации не может прочитать ни граф, ни файлы, ни историю первого.

После первого сценария провести несколько наблюдаемых проб с потенциальными пользователями: где неясна настройка, какие сообщения об ошибках непонятны, какие источники нужны следующими. Числовые цели конверсии и производительности устанавливать после этого, не придумывать сейчас.
